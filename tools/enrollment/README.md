# Real administrator enrollment

The tool prepares SQL and a single-use invitation using a real name/contact provided by the owner. It creates no remote records itself. Never use placeholder identities or send passwords/API keys in chat. The requested school administrator has no platform-operator or superadmin privileges.

Supply private JSON with explicit `fullName`, `email` and/or `mobile`, and `schoolCode`. Run `node prepare-admin.mjs <private-real-identity.json> <new-private-output-directory>`. Files are exclusive-create with mode 0600; the token is not printed, placed in a URL or stored in the database. Review ownership, school and duplicate-contact check. Apply migration 0004 before reviewing/applying SQL against the verified exact D1 binding through the authenticated Cloudflare owner.

The SQL contains one INSERT into the owner-only enrollment request table. Its reviewed database trigger validates current school status/contact uniqueness and creates the pending user/invitation within the same SQLite statement transaction. Missing school fails the NOT NULL constraint; duplicate contact or later trigger failure rolls back the request and all writes. No separate BEGIN/COMMIT or multi-request transaction assumption is used.

The pending user has status `invited` and unusable password marker `!`; it cannot authenticate. The private invitation expires in 24 hours, binds one school/admin and must be handed to the owner securely. Redemption atomically sets the user's chosen secure password, grants only admin membership and consumes the invitation. It does not activate an unconfigured school or issue a session. Revocation and expiry block redemption. Concurrent second use fails the DB guard. Current FREE_AUTH_CPU_BLOCKER means enrollment and login remain closed pending a verified compatible secure path.

## Owner-generated administrator access key (selected 9 October)

`prepare-access-admin.mjs <real-identity.json> <private-secret-file> <new-private-output-directory>` requires real `fullName`, `email` or `mobile`, and the verified `schoolCode`/`schoolId`. It generates a fresh 256-bit access key and HMAC tag bound to school/user. It never hashes chosen passwords or modifies imported bcrypt credentials. One generated SQL insert activates only the genuine administrator identity and role; school status remains unchanged. The private credential file is mode 0600 inside a mode 0700 directory. No credential is printed or sent. Apply only after migration 0005 against the verified account/database.

Deploy `ADMIN_ACCESS_KEY_SECRET` using Wrangler secret stdin from the same private secret file used for preparation. Never change it casually: existing key tags depend on it. Authentication gate remains disabled until the selected path has been tested; scalar crypto probes alone are not complete D1 login acceptance. For an unconfigured school, login issues a restricted setup session: dashboard, school/profile and directory reads, feature status and logout only. It cannot activate school, create records, access student files, use mobile sync or perform platform operations.

Keys expire after 90 days; current credential revocation/expiry is checked on every authorized request. Owner rotation must generate a new random key, digest and credential ID, update the same genuine school/user credential atomically and revoke that user's sessions; retaining a credential ID would allow old sessions to survive rotation. No browser self-service rotation/recovery endpoint is implemented yet. Keep private owner recovery tooling and database access under the actual Cloudflare owner.
